## 釐清：接下來只需要三把金鑰，不是四把

原本以為要湊齊 LINE ×2 + OpenRouter + Firebase 四把才能動。實際不用。

**`GOOGLE_APPLICATION_CREDENTIALS` 本機階段完全不需要。**
`docker-compose.yml:45` 給三個服務都帶了 `FIRESTORE_EMULATOR_HOST=firestore:8080`，
Firestore SDK 看到這個變數就改連模擬器，**不做任何認證**。
Firebase service account 是上 Modal 才需要的東西。

Firebase 不在其中 —— 程式本身就是這樣設計的。

## 驗證路徑拆成兩段

webhook 需要**公開 HTTPS 網址**，LINE 打不到 `localhost:8100`。
但日報推播本身不需要 webhook —— 它只是使用者註冊的管道。

LINE Developers Console 的 Basic settings 分頁有一欄 **Your user ID**（`U` 開頭），
抄下來就能直接往 Firestore 模擬器塞一筆使用者，跳過整個 webhook 環節。

```
第一段（3 把金鑰）   手動塞 user → 排程 → 抓 104 → 摘要 → 推到手機
第二段（要公開網址） ngrok/cloudflared → LINE 打得到 webhook → 加好友自動註冊
```

**先做第一段。** 它暴露的問題最多（LINE 訊息長度上限、LLM 回應解析、
Firestore schema 是否合用），且不需要隧道工具。

## 缺口：Modal 上的 Firebase 憑證無程式碼路徑（當天補完）

`src/store/firestore.py:37` 用 `firestore.AsyncClient(project=...)`，走 Google 的
預設憑證機制（ADC）—— 它讀 `GOOGLE_APPLICATION_CREDENTIALS` 指向的**檔案路徑**。

但 CLAUDE.md 第 6 節規劃的 Modal Secret 是 `FIREBASE_SERVICE_ACCOUNT`，
內容是 **JSON 字串**。Modal Secrets 只能給環境變數，給不了檔案。

**目前沒有任何程式碼把 JSON 字串轉成憑證。** 本機用模擬器碰不到，
會在 Modal 部署那一刻才炸。

### 修法

新增 `build_client(settings)`，把「挑憑證來源」這件事從 `JobStore.__init__`
獨立出來成為可測的接縫。三條路各自明確：

| 環境 | 判斷依據 | 憑證 |
| :--- | :--- | :--- |
| 本機 Compose | `FIRESTORE_EMULATOR_HOST` 有值 | 無（SDK 用匿名憑證） |
| Modal | `FIREBASE_SERVICE_ACCOUNT` 有值 | `from_service_account_info(json.loads(...))` |
| 一般機器 | 兩者皆無 | ADC（`GOOGLE_APPLICATION_CREDENTIALS` 檔案） |

**優先序刻意是「模擬器優先」**：本機若不小心留著雲端金鑰，也不會誤連到正式資料庫。

### 順手處理兩種貼錯

這條路徑只有部署當下會走到，錯誤訊息難懂會很難查，所以把兩種常見失誤攔下來換成人話：

1. **JSON 少複製一段** → `RuntimeError`，訊息指名 `FIREBASE_SERVICE_ACCOUNT`
2. **貼成 Firebase 網頁版設定**（`apiKey` / `authDomain`）→ 明講那與 service
   account 金鑰不是同一份東西

另外，憑證裡的 `project_id` 與 `FIREBASE_PROJECT_ID` 不一致時發 WARNING ——
這種錯不會讓程式爆掉，只會安靜地寫進錯的資料庫。

## 改用免費的摘要供應商，順便解除供應商綁定

原訂 OpenRouter 要付費，對個人 side project 不合理。查證後有兩條免費路：

| 選項 | 免費額度 | 顧慮 |
| :--- | :--- | :--- |
| **Google AI Studio** | 5-15 RPM / 100-1000 RPD，免信用卡 | — |
| OpenRouter `:free` 模型 | 20 RPM / 50 RPD（未儲值） | 免費池多為中國模型，**中文輸出可能是簡體** |
| 自架 Ollama | 「免費」 | 在 Modal 上跑推論的運算費用遠高於直接呼叫 API |

**選 Google AI Studio。** 決定性因素不是額度而是**繁體中文** —— 日報的
prompt 明確要求繁中，而 OpenRouter 免費池以 DeepSeek、Qwen 為主，
輸出容易跑成簡體，等於要多花時間調 prompt 再驗證。

### 真正的收穫：發現這件事根本不該綁供應商

改的時候才注意到，`summarize()` 打的是標準 OpenAI 相容 `/chat/completions`
—— 換供應商本來就只是換三個字串。原本卻把 `openrouter.ai` 的網址寫死在
模組常數裡，等於把一個「設定」硬編成「架構」。

於是連同解除綁定一起做：

| 之前 | 之後 |
| :--- | :--- |
| `_API_URL` 常數寫死 | `LLM_API_URL` 環境變數，有預設值 |
| `OPENROUTER_API_KEY` / `OPENROUTER_MODEL` | `LLM_API_KEY` / `LLM_MODEL` |
| `src/summarizer/openrouter.py` | `src/summarizer/llm.py` |

現在要換回 OpenRouter、改用 Groq 或自架 LiteLLM，都只需改 `.env`。

測試也跟著調整：原本 `respx` 直接 mock 那個寫死的常數，現在改用
`monkeypatch` 固定一個假端點，**測試結果不再隨本機 `.env` 指向哪家而變**
（與 8/2 踩過的 `.env` 污染坑同一類問題）。

### 已知的額度隱憂：該批次摘要

目前是「一筆職缺一次 API 呼叫」，單一使用者一天最多 20 次
（`MAX_JOBS_PER_DAY`）。免費額度撐得住個位數使用者，再多會撞牆。

**解法不是換供應商，是批次摘要** —— 一次請求處理 10 筆，請求數降 10 倍，
順便少 10 倍網路往返。這次沒做，記入 CLAUDE.md 第 9 節待辦。

```

ruff check .  →  All checks passed!
```
