## 決策：部署架構選 A（Compose 開發 + Modal 部署）

原 CLAUDE.md 指定 Modal，但開發環境要求用 Docker Compose。兩者不同層級，
需決定分工方式。評估三個選項：

| 選項 | 電腦關機日報還發 | Docker 學習量 | 維護負擔 |
| :--- | :--- | :--- | :--- |
| **A. Compose 開發 + Modal 部署** | ✅ 發 | 中高 | 中（雙入口） |
| B. 全部自架（含 cloudflared 隧道） | ❌ 停 | 高 | 高 |
| C. Compose 只當開發容器 | ✅ 發 | 低 | 低 |

**選 A**。關鍵理由：日報的核心價值是每天準時送達，B 把可靠性綁在本機電源狀態上，
等於拿產品核心價值換學習機會。A 仍能學到多服務編排、volume、網路、healthcheck。

**衍生設計**：核心邏輯寫成平台無關的 `src/`，`modal_app.py` 與 `scheduler/run.py`
都只是薄入口。日後若要改成 B（搬去 VM 自架），只需換入口檔，`src/` 一行不動。

**雙入口的環境漂移風險**：用 `modal.Image.from_dockerfile("Dockerfile", stage="production")`
讓 Modal 直接讀同一份 Dockerfile，本機與雲端共用單一環境定義。

## 踩到的坑

### 1. 中文測試函式名不能含空白

```
E   File "/app/tests/unit/test_webhook_signature.py", line 47
E       def test_缺少簽章 header 被拒絕() -> None:
E   SyntaxError: expected '('
```

**原因**：Python 識別字允許中文，但不允許空白。混寫中英文時很容易誤加空格。
**解法**：改用底線 `test_缺少簽章_header_被拒絕`。

### 2. ruff N802 誤判中文測試名

27 個 N802 `invalid-function-name` 錯誤，全部來自中文測試函式名 —— ruff 認為
函式名「必須小寫」，但中文沒有大小寫概念。

**解法**：`pyproject.toml` 加 per-file-ignores，只對 `tests/**` 關掉 N802。
不改測試命名風格 —— 中文測試名讓測試報告直接讀得懂在測什麼，價值高於這條規則。

### 3. Port 8000 / 8080 被佔用

```
Error response from daemon: ports are not available: exposing port TCP 127.0.0.1:8080
bind: Only one usage of each socket address is normally permitted.
```

**原因**：另一個專案 `stock-information-platform-api-1` 正佔用 8000；8080 被 wslrelay 佔用。

**排查過程**：
1. `docker compose ps` 顯示服務沒起來，但 `curl localhost:8000/health` 卻回 200
   → 表示回應來自別的程式，不是本專案
2. `Get-NetTCPConnection -LocalPort 8000` 找出 PID → `com.docker.backend`
3. `docker ps -a` 找到真正佔用的容器

**解法**：host port 改用環境變數 `${API_PORT:-8100}` / `${FIRESTORE_PORT:-8181}`，
容器內部 port 維持 8000 / 8080 不變（容器間走內部網路，不受 host port 影響）。
之後換 port 只需改 `.env`，不用動 `docker-compose.yml`。

**教訓**：多專案並行時，host port 不要寫死。
