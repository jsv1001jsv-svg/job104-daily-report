## 決策：為什麼今天不繼續攻 Cloudflare

三個選項評估：

| 選項 | 進度確定性 | 說明 |
| :--- | :--- | :--- |
| 繼續攻 Cloudflare（patchright / 持久化 profile） | ❌ 低 | 可能整天零產出，且 CLAUDE.md 已誠實記錄「有可能做不到」 |
| **先繞開，補完其他環節** | ✅ 高 | 選這個 |
| 重新評估資料來源（改用台灣就業通） | — | 言之過早，抓取還沒真正判死刑 |

**理由**：抓取失敗與否，pipeline / summarizer / store / webhook 的邏輯都不會變。
這些模組的驗證不該被一個外部封鎖擋住。等抓取解決時，其餘環節已經是可信的，
屆時只需接上一條驗證過的資料來源。

反過來說，若今天先攻 Cloudflare 而失敗，等於一天下來既沒抓到資料，
其他模組也依然沒有安全網。

### 測到的關鍵規則

補測試的過程中，把幾條「錯了會造成資料遺失」的規則明確釘住：

1. **推播成功才標記已看過**（`test_推播失敗不標記已看過以便明天重試`）
   順序反過來的話，LINE 額度用完那天的職缺會永遠不再出現。
2. **單一使用者失敗不影響其他人**（`test_一位使用者抓取失敗不影響其他人`）
   一個人的搜尋條件打不到 104，不該讓其他人收不到日報。
3. **webhook 處理失敗仍回 200**（`test_單一事件失敗仍回_200`）
   回 500 會讓 LINE 不斷重送整批事件，造成重複處理。
4. **各使用者的已看清單互不影響**（`test_各使用者的已看清單互不影響`）
   多使用者版的核心前提。
5. **摘要失敗降級而非拋例外**
   使用者收到品質稍差的日報，好過收不到日報。

## 踩到的坑

### 1. `slots=True` 的 dataclass 沒有 `__dict__`

想用 `Job(**{**job.__dict__, "description": ...})` 快速造變體，直接 `AttributeError`。

**原因**：`@dataclass(slots=True)` 用 `__slots__` 取代實例字典，省記憶體也擋住動態加屬性。
**解法**：改用 `dataclasses.replace(job, description=...)`，本來就是 frozen dataclass 的正規做法。

### 2. host 上沒有專案依賴

Docker Desktop 沒開，`python -m pytest` 直接 `ModuleNotFoundError: pydantic_settings`。

**解法**：建 `.venv`（已在 `.gitignore`）跑單元測試。
單元測試不碰容器內的服務，host 上跑結果一致，回饋快很多。
整合測試（Firestore 模擬器）仍需走 Compose。

### 3. 測試讀到本機 `.env` 導致結果不穩

`Settings` 預設 `env_file=".env"`，測「缺少金鑰時應拋錯」時，
本機 `.env` 有值就不會拋，測試在別人機器上會壞。

**解法**：測試一律用 `Settings(_env_file=None, ...)` 明確給值，不依賴環境。
